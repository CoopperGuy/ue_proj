# 방 탐색·전투·보상 흐름

## 구현 범위

한 층에서 시작방 → 일반 전투방 → 보물방 탐색 → 보스 처치 → 보상 선택 → 기존 클리어 화면으로 이어진다. 기존 방·몬스터·아이템·스킬 데이터와 HUD를 재사용한다.

| 방 | 처리 |
|---|---|
| 시작방 | 전투·보상 없음 |
| 일반방 | 첫 클리어 때 한 번 추첨: 추가 보상 없음 50%, 골드 30%, 회복 15%, 일반 등급 장비 5% |
| 보물방 | 전투 없이 보상대 제공. 새 스킬·보유 스킬 강화·장비 중 하나를 확인하고 획득 |
| 보스방 | 서로 다른 후보 두 개 중 하나 선택. 획득 성공 후 클리어 화면 표시 |
| 복도 | 전투·보상 없음 |

일반방 골드는 `20 + 캐릭터 레벨 × 5`, 회복은 최대 체력의 25%다. 체력이 가득 차거나 인벤토리가 가득 차면 보상이 남는다. 방에 속한 몬스터의 기존 아이템 드롭을 끄고 경험치 지급은 유지한다.

보상대에 가까이 가서 클릭한다. 보물방·보스방은 기존 카드 UI에서 내용을 확인한다. 장비는 실제 접두·접미 옵션을 미리 생성해 설명에 표시하며, 획득할 때 다시 생성하지 않는다. `Esc`로 창을 닫고 인벤토리를 정리한 후 다시 열 수 있다. 보스 보상을 받은 후에는 같은 보상대에서 클리어 화면을 다시 열 수 있다.

보상대는 엔진 기본 메시·조명·텍스트로 생성한다. 별도의 Blueprint를 만들 필요는 없다. 월드의 간단한 표지는 기본 TextRender 폰트를 사용하는 영문이며, 카드와 안내 문구는 한국어다. 최종 아트와 카드의 긴 설명 줄바꿈은 에디터에서 확인할 대상이다.

## 층 생성과 몬스터 배치

- 기본 그리드는 8~10칸 × 8~10칸이다. 일반 전투방 6개, 보물방 1개, 보스방 1개를 목표로 하며 복도와 시작방은 전투방 수에서 제외한다.
- 연결된 방의 그래프를 살펴 보스까지의 경로 밖에 있는 방을 보물방으로 우선 선정한다. 같은 조건에서는 막다른 방을 우선한다.
- 방 크기·포트·인접 규칙에 따라 목표 배치가 안 나올 수 있다. 최대 32번 생성하고 보스가 있는 배치를 우선 보존한다. 목표를 채우지 못하면 로그에 알린다. 실제 에셋으로 목표 충족률을 확인해야 한다.
- `FMapSpawnInfo.EncounterPattern`에서 `Automatic`, `Ring`, `TwoFlanks`, `Grid`를 선택할 수 있다. 기존 행은 기본값 `Automatic`으로 동작한다.
- 방 ID를 바탕으로 몬스터 그룹, 수, 배치 구도를 결정한다. `SpawnWeight`가 양수인 행이 있으면 가중치를 사용하고, 모두 0인 기존 데이터는 균등 추첨한다.
- 내비게이션 투영, 방 중심 주변의 범위, 플레이어와의 거리, 몬스터 간 간격, 충돌을 검사한다. 장애물 때문에 모든 수를 배치할 수 없으면 검증된 위치만 사용하고 실제 생성 수를 기준으로 클리어를 판정한다.
- 몬스터 종류·AI·애니메이션 에셋을 새로 추가한 것은 아니다. 기존 종류의 배치와 선정 방식을 변경했다.

## 저장과 중복 방지

버전 1 저장에는 다음 정보가 포함된다.

- 실제 방 배치, 고유 ID, 보물방 지정, 시작방, 클리어한 방
- 보상이 없는 결과까지 포함한 추첨 결과, 후보별 실제 장비 인스턴스, 수령 여부
- 골드·레벨·경험치·체력·마나·인벤토리·장착 장비
- 보유 스킬, 레벨, 해금한 강화, 적용한 강화, 퀵슬롯

보상 결정은 `UDiaRewardSubsystem`, 표시·상호작용은 `ADiaRoomRewardActor`, 기존 UI 연결은 `ADungeonGameMode`가 담당한다. UI가 전달한 보상 내용을 그대로 지급하지 않고 방 ID와 후보 번호로 원본 기록을 조회한다. 지급 성공 후에만 수령 완료로 표시하며 중복 클릭·재진입을 차단한다.

전투 중, 불러오는 중, 보상 적용 중에는 저장을 거절한다. 불러오기 전에는 배치 크기·고유 ID·보상 식별자를 검사한다. 기존 버전 0 저장에는 방 배치가 없으므로 새 층의 입구에서 시작하며, 예전 파일에 없던 골드·스킬 성장 정보는 복구할 수 없다.

## 조정 위치

| 대상 | 소스 |
|---|---|
| 일반방 드롭 비율 | `ARPG/public/Types/DiaRoomRewardPolicy.h` |
| 보상 후보·골드·회복·기존 빌드 친화도 연결 | `ARPG/private/System/DiaRewardSubsystem.cpp` |
| 방 수·그리드 기본값 | `ARPG/public/System/DiaMapGeneratorSubsystem.h` |
| 보물방 선정·생성 재시도 | `ARPG/private/System/DiaMapGeneratorSubsystem.cpp` |
| 몬스터 배치 구도 | `ARPG/private/System/MonsterSpawnSubSystem.cpp` |
| 보상대 표현·획득 거리 | `ARPG/private/Actor/DiaRoomRewardActor.cpp` 및 보상 서브시스템의 획득 검사 |
| 저장 스키마·검사 | `ARPG/public/System/DiaSaveGame.h`, `ARPG/private/System/DiaSaveGame.cpp` |

성장 보상은 스킬 계열과 장비 계열을 먼저 선택한다. 둘 다 남아 있으면 스킬 계열 75%, 장비 25%이며, 스킬 후보는 기존 빌드 친화도에 따른 새 스킬 후보와 보유 스킬의 미해금 강화를 사용한다. 보스에는 보유 스킬 레벨업도 포함한다. 다른 방에서 아직 수령하지 않은 동일 스킬 보상은 후보에서 제외한다.

아이템 테이블에는 일반 등급의 장착 가능한 장비가 최소 하나 필요하다. 보스용 성장 후보는 서로 다른 항목이 최소 두 개 필요하다. 데이터가 부족하면 보상을 소비하지 않고 오류를 남기며 재시도할 수 있게 한다. 2026-09-22 MCP 점검에서 일반 장비 후보와 보스의 서로 다른 두 후보를 확인했다.

## 검증 상태

- **통과:** 실제 드롭 정책 헤더를 포함한 독립 C++ 테스트를 MSVC `/std:c++17 /W4 /WX`로 컴파일하고 실행했다. 전체 100개 입력과 모든 확률 경계값을 검사했다.
- **통과:** 저장소의 줄바꿈 설정을 적용한 `git diff --check`, 변경한 C++ 파일 35개의 괄호 균형·generated header 순서 검사. 이는 Unreal 컴파일을 대신하지 않는다.
- **통과:** 2026-09-22 실행 중인 에디터의 MCP에서 `ARPG.RoomRewards.ProbabilityBoundaries`, `SnapshotValidation` 자동화 테스트를 실행했다. 새 네이티브 보상 액터와 테스트가 로드된 것도 확인했다.
- **수정 후 재실행 대기:** `SaveRoundTrip`은 테스트용 `UDiaRewardSubsystem`을 GameInstance 없이 생성해 ClassWithin ensure가 발생했다. `UGameInstance`를 만들고 이를 Outer로 전달하도록 테스트 소스를 수정했다. 현재 에디터에는 수정 전 바이너리가 로드돼 있으며, 컴파일 승인을 요청한 상태다. 이 테스트의 최종 통과는 아직 확인하지 않았다.
- **통과:** PIE에서 시작방 1개·일반 전투방 6개·보물방 1개·보스방 1개 생성, 일반방 진입 및 랩터·좀비/폭발형 스폰, 처치 후 문 열림과 무보상 처리, 보물방 장비/스킬 수령, 보스의 서로 다른 두 후보 중 하나 선택 및 클리어 안내 활성화를 확인했다.
- **통과:** 보상창 Esc 닫기·재열기, 430cm 거리에서 획득 거부 및 제단 유지, 가까이 복귀한 뒤 같은 후보 수령, 성공 후 창 닫힘과 제단 제거, 수령한 보스 제단에서 보상 선택창 없이 클리어 안내 재열기를 확인했다.
- **검증 방법:** PIE 캐릭터를 문 트리거로 이동시키고 Enhanced Input으로 실제 클릭 처리 경로를 실행했다. 클리어 검증에는 게임의 `DiaGameplayEffect_Damage`를 MCP로 적용했다. 수동 전투 난이도·모든 통로의 이동 가능성·모든 생성 시드의 배치 품질을 검증한 것은 아니다.
- **미실행:** 실제 저장 슬롯을 통한 저장·로드 왕복, 인벤토리 가득 참/최대 체력에서의 획득 실패, 장비·스킬 강화의 저장 후 실제 전투 효과 비교. 기존 사용자 저장 슬롯은 변경하지 않았다.

## 2026-09-22 MCP 에셋 수정

아래 에셋 6개를 수정해 저장했으며 `is_dirty=false`를 확인했다.

- `/Game/Datatable/DT_SpawnGroupTable`: `TestRoom`은 Ring, 랩터/좀비 가중치는 2/3으로 설정했다. 기존 랩터 가중치 0으로 인해 추첨에서 빠지던 문제를 해소했다. `NewRow`는 TwoFlanks로 설정해 좀비·폭발형 그룹에 연결했다. 보스 그룹은 유지했다.
- `/Game/Map/PackageInst/BPP_RoomLarge1x2`, `BPP_RoomLarge2x1`, `BPP_RoomLarge2x2`: 벽 32개의 동일 부모 중복 참조를 Unreal SubobjectDataSubsystem으로 정리했다. 메시·위치·회전·크기가 전후 동일함을 검사했고, 세 Blueprint가 컴파일을 통과했다. 수정 후 PIE에서 해당 Reparenting 경고가 재발하지 않았다.
- `/Game/UI/HUD/WBP_HUDWidget`: 보상 패널을 화면 전체 앵커에 연결해 배경 어둡게 처리가 화면 전체에 적용되도록 수정했다.
- `/Game/UI/Rewards/WBP_RewardCard`: 아이콘 브러시를 Image/흰색 tint로 수정해 실제 보상 아이콘을 표시하도록 했다.

보상 카드·선택 패널·HUD의 Widget Blueprint 컴파일을 확인했다. 수정한 UMG의 계층을 다시 읽고 PIE 화면에서 배경과 스킬 아이콘 표시를 확인했다. 테스트 PIE는 종료했다.

## 에디터에서 확인할 순서

1. 변경된 USTRUCT/UCLASS를 반영해 프로젝트를 컴파일한다. 새 보상 액터가 있으므로 Live Coding만으로 반영됐다고 판단하지 않는다.
2. Automation에서 `ARPG.RoomRewards` 테스트를 실행한다.
3. 새 게임에서 시작방, 전투방 수, 보스 접근 경로, 보물방 하나가 생성되는지 확인한다. 여러 번 생성해 목표 미달 로그와 끊어진 문이 없는지도 확인한다.
4. 일반방을 클리어해 무보상일 때 창이 뜨지 않는지 확인한다. 드롭을 받지 않은 상태로 저장·로드해 위치와 결과가 유지되는지 확인한다.
5. 인벤토리를 채우거나 체력을 가득 채운 상태에서 획득 실패 후 보상이 남는지 확인한다. 빈 공간 또는 체력 손실을 만든 후 같은 보상을 획득한다.
6. 보물방 카드에서 설명을 확인하고 `Esc`로 닫았다가 다시 연다. 스킬·강화 또는 장비를 받고 재입장해 중복 지급이 없는지 확인한다.
7. 보스 보상 두 개 중 하나를 선택한다. 클리어 화면이 열리고 나머지 후보를 받을 수 없는지 확인한다. 저장·로드 후 클리어 화면을 다시 열 수 있어야 한다.
8. 장비를 장착하고 스킬 레벨·강화·퀵슬롯을 바꾼 후 저장·로드한다. 아이템 옵션, 장비 스탯, 골드, 체력·마나·경험치, 스킬 레벨과 실제 강화 동작을 비교한다.
9. 몬스터 스폰 실패 시 문이 열린 상태로 재진입 가능한지, 부분 생성 실패로 남은 몬스터나 중복 경험치가 생기지 않는지 확인한다.

상점·열쇠·도전방은 이 변경에 포함하지 않았다. 먼저 위 흐름의 실제 플레이 검증과 보상 빈도 조정이 필요하다.
